# Матрица приёмки и автоматизации

Контракт: [реализованное поведение](current-behavior.md). ID в первом столбце
присутствует в названии Cypress-теста; `npm run e2e:trace` проверяет соответствие
в обе стороны. Повтор ID для ролей/размеров экрана — параметризация одного сценария.
Все строки UI ниже автоматизированы. Это не означает полного покрытия всех
комбинаций, реального Telegram API или server authorization одним Cypress.

## Ручная приёмка реальных Telegram-клиентов

Перед объявлением полной готовности проверять на тестовом боте/чатах, не
рассылать реальные уведомления ради smoke без согласованной аудитории.

1. Подключение администратором в forum и обычной группе без /setup, обнаружение
   старой темы сообщением, командная/reply-клавиатура и Main Mini App ссылка.
2. iPhone и Telegram Desktop: мобильная ширина Mini App, открытие формы после
   прокрутки, экранная клавиатура, поворот, safe area, скролл последнего поля,
   видимые CTA/крестик, закрытие selector каждым способом.
3. Два пользователя с разным членством А/Б, прямые ссылки, удаление из группы,
   повтор после сессии старше TTL. Проверить API-отказ, а не только скрытую кнопку.
4. Реальные requestWriteAccess → private update → обновление разрешения,
   /stop → повторное открытие не включает ЛС → личная /start включает.
5. Создание с местом или online URL, публикация в верную тему; правка без ЛС и
   с явной ЛС; RSVP разных людей, скрытые counts до ответа, независимые маркеры.
6. Рассылка строго тестовой группе: получивший/запретивший/вышедший/сменивший ответ;
   delivery statuses, а не обещание гарантированной доставки.

Ручная матрица не отмечается выполненной автоматически после зелёного Cypress.
Новые CRUD тем, плановые reminders и AI-разбор исключены из текущей приёмки.

## Политика

- FSD и kebab-case для авторских frontend-файлов.
- Tailwind CSS — выбранный пользователем инструмент стилизации интерфейса.
  Общие дизайн-токены и базовые компоненты используются повторно.
- Backend проектируется по доменным сценариям; исходное предложение —
  модульный монолит, а не отдельный сервис на каждую таблицу.
- Права проверяются на сервере для конкретного чата и события.
- Покрытие — минимум 90% строк и ветвей отдельно по frontend/backend.
- Миграции и persistence проверяются на целевом PostgreSQL.
- Рабочая ветка → PR в develop → PR develop в main.
- Прямые push/force-push в main и develop запрещены.
- Релизные артефакты и deployment — только по проверенному версионному тегу.

Установщик сохраняет инструкции; он не настраивает автоматически GitHub branch
protection, обязательный CI и release gates. Их реальный статус проверяется
отдельно. Bootstrap workflow проверяет направление PR и git diff --check;
полноценные lint/types/tests/coverage и анализ миграций добавляются с приложением.
Whitespace проверяется для файлов проекта; `.agents/skills` исключены, поскольку
это точная поставка внешнего набора с checksums (в исходных скриптах есть пробелы
в конце строк). Поставляемые навыки не форматировались и не модифицировались.

По запросу владельца 2026-10-15 репозиторий сделан публичным.
Защита main/develop разделена на два независимых механизма:
`.github/branch-protection.json` требует PR и успешных проверок
Branch policy / Repository hygiene, запрещает force-push и удаление веток,
применяется к администраторам без обхода.
`.github/review-ruleset.json` требует одно одобрение, но разрешает владельцу
`SosnovichIvan` обходить именно это правило при слиянии PR. Поэтому владелец
может объединять собственные PR без чужого одобрения, после успешного CI.
Исключение привязано к аккаунту владельца, а не ко всем администраторам.

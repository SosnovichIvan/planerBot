# Автоматическое подключение и компактный календарь

## Контракт

Вход: Telegram `my_chat_member`, сообщения групп/супергрупп, Mini App API.
Владелец подключений — ChatRepository; прав — ChatAccess/EventService.
Инварианты: бот работает только с правами администратора; читать может текущий
участник; создавать любым способом — только текущий администратор целевого чата.
Старое значение `creation_policy=members` больше не разрешает импорт участникам.
API настройки принимает только `admins`; список чатов возвращает `admins`.

Назначение бота администратором регистрирует чат и общий поток одной транзакцией,
затем устанавливает команды для участников и администраторов и отправляет кнопку.
Повторное изменение прав администратора не отправляет повторное приветствие.
Потеря прав отключает чат. `/setup` оставлен как необязательное переименование.
Для уже добавленного бота без регистрации нужно повторно выдать права администратора.

Темы регистрируются по сообщениям и `forum_topic_created`/`forum_topic_edited`.
Существующие темы Bot API не перечисляет: до первого сообщения тема может
отсутствовать, её имя до получения служебного события — «Тема N».
Для обычной группы внутренний topic_id=1 обозначает общий поток;
при отправке карточки message_thread_id не передаётся.

Telegram не позволяет произвольно добавить Mini App в меню группы:
setChatMenuButton относится к личному диалогу, а меню вложений ограничено
категорией ботов. Поддерживаемый путь — команды чата и сообщение с deep link.
Main Mini App должен быть настроен в BotFather.

## Данные и отказные сценарии

Схема PostgreSQL 17 и миграции не меняются. До обработчика сообщения выполняется
get чата (PK) и тем (PK chat_id,thread_id), без SQL N+1. При новой теме/изменении
имени — атомарные upsert чата и темы. ON CONFLICT DO NOTHING сохраняет имя
и enabled существующей темы при автоматическом обнаружении. Явное новое имя
обновляет только title, не настройки и не enabled. Уникальный составной PK
защищает повторную конкурентную регистрацию. Новые индексы не требуются.
Планы/latency на production-объёме не измерены; дополнительное чтение на сообщение
нужно учитывать при росте нагрузки. Сетевые вызовы не входят в DB-транзакцию;
ошибка установки команд не откатывает регистрацию и не расширяет права.

Политика администраторов несовместима со старой формой настроек members:
старый клиент получит 422, а не сможет вернуть разрешение участникам.
Обновлять API, polling, worker и frontend в одном релизе после PR develop → main
и нового версионного тега. Production в рамках реализации не изменяется.
Данные/тома не удаляются. Исправление — следующий релиз; откат на старый код
вновь включит прежнюю политику members и потому не является безопасным rollback.

## Приёмка

Автотесты проверяют права, старую политику members, подключение без setup,
обычную группу и forum, обнаружение/переименование тем, disabled и конкурентный
upsert на PostgreSQL, селект чата/всех, отсутствие фильтров и кнопки в шапке.
Вручную в Telegram проверить добавление/повышение бота, открытие Mini App,
создание администратором в группе без тем и в теме, отказ участнику и выход из чата.
Браузерный mock SDK/API не заменяет приёмку в Android/iOS/Desktop.

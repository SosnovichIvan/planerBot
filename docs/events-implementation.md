# Контракт событий и настроек

Статус: согласованный этап реализован и проверен локально. Нагрузка неизвестна; начальная версия
для пилота, без обещаний SLA.

## Сценарии и права

Администратор настраивает IANA timezone, тег события, разрешённые темы,
авторов (администраторы / все участники) и подтверждение импорта. По умолчанию
UTC, #событие, только администраторы. Сообщения обычных участников всегда
попадают на подтверждение. Список ожидающих виден только администраторам чата.

В календаре администратор выбирает управляемый чат и включённую тему,
заполняет название, дату/время, формат и место встречи либо «Место уточняется».
Сохранение и задание публикации атомарны. /event в нужной теме принимает
тот же строгий шаблон без тега и создаёт событие с публикацией ботом.
В личном диалоге /event даёт кнопку персонального календаря; форму там открывает
пользователь с правами администратора хотя бы одного подключённого чата.
Сообщение с настроенным тегом импортируется без повторной публикации;
бот отвечает подтверждением. Редактирование исходника обновляет ту же запись.
Снятие тега не отменяет событие: отмена выполняется явно в календаре.

Просмотр и изменение проверяют текущие права пользователя и бота в целевом
чате. Тема события принадлежит тому же чату (составной FK в БД).
После создания тема неизменяема; перенос выполняется созданием нового события
и отменой старого, чтобы не оставлять карточку в прежней теме.

## HTTP-контракты

FastAPI schemas — источник OpenAPI и frontend-типов. Все endpoints требуют tma.

- GET /api/chats: доступные чаты, настройки, темы (админу включая выключенные).
- PUT /api/chats/{id}/settings: полный набор настроек и текущая version;
  409 при конкурирующей правке, форма сохраняет введённые значения.
- GET /api/events: диапазон локальных дат [start,end), максимум 62 дня,
  необязательный chat_id/topic_id/tag. Максимум 200 событий, has_more при превышении;
  порядок local_date, starts_at, id. Pending виден только администраторам.
  Многодневные события включаются по пересечению диапазона; окончание в 00:00
  первого дня периода не считается пересечением.
- POST /api/chats/{id}/events: EventInput и Idempotency-Key (UUID).
  Повтор того же тела возвращает то же событие; другое тело с тем же ключом — 409.
  Ключ ограничен чатом и автором; server event_id не совпадает с клиентским ключом.
  Пространство ключей формы отделено от идентификаторов импорта сообщений.
- PUT /api/chats/{id}/events/{event_id}: EventInput и version, optimistic lock.
- POST .../{event_id}/approve или /cancel: version и проверка администратора.
- POST .../{event_id}/retry: повтор известного отказа; для unknown требуется
  ack_duplicate_risk. Endpoint не обходит текущее членство/права.

Формат времени: start_date/end_date YYYY-MM-DD, start_time/end_time HH:MM,
без start_time — весь день. Часовой пояс берётся из настройки чата и сохраняется
в событии; изменение настройки не сдвигает существующие события.
Переходы DST с отсутствующим или неоднозначным локальным временем отклоняются.
Ссылки — только HTTP(S), длины полей ограничены до размера Telegram-карточки.

## Данные и транзакции

Миграция 0002 расширяет существующие chats/topics с server defaults, сохраняя
подключения. Добавляет events и publications. Старый каркас совместим с новыми
полями; новая версия требует upgrade до запуска. Backfill defaults — PostgreSQL
для маленькой новой схемы; длительность на большой базе не измерена.

| Данные | Владелец / ключ | Инварианты и lifecycle |
| --- | --- | --- |
| Настройки chats | Модуль чатов, PK chat_id | NOT NULL, version >=1, IANA zone валидируется до записи |
| topics.enabled | Модуль чатов, PK chat_id/thread_id | Старые темы включены; исключение не удаляет события |
| events | Модуль событий, UUID PK | FK chat/topic; source(chat_id,message_id) UNIQUE; version>=1 |
| publications | Доставка, event_id PK/FK | Одно задание на событие, desired_version, status, lease, message_id |

Офлайн-место, адрес, карта, онлайн-ссылка и описание — приватные данные чата.
Сырые сообщения не хранятся; сохраняются структурированные поля и ссылка-источник.
Удаление чата каскадирует темы, события и задания; продуктовая отмена — soft state.
Downgrade удаляет новые данные, применять только к изолированной тестовой БД;
для реального отката нужны backup или forward fix.

Создание/изменение события + обновление задания выполняются одной транзакцией.
UNIQUE и optimistic version обеспечивают повторы и конкуренцию; сетевых вызовов
внутри транзакции нет. Импорт блокирует исходную запись и игнорирует старые
ревизии по (время сообщения/правки, update_id). Событие из пользовательского
сообщения не порождает вторую исходящую карточку.

Индексы: UNIQUE источника защищает импорт при гонке; events(chat_id,local_date)
соответствует фильтру чатов и диапазону календаря; publications(status) обслуживает
очередь. Список читает bounded IDs и затем события с чатами/темами/публикацией
одним bounded join (два SQL-запроса, без N+1);
обязательные сетевые проверки членства остаются вне SQL. План/latency на реальной
нагрузке ещё не измерены.

## Доставка

Отдельный worker выбирает pending с FOR UPDATE SKIP LOCKED, фиксирует sending
и lease до сети. Отправка/редактирование карточки — вне транзакции, после
повторной проверки прав. Успех сохраняет message_id; новая правка во время
отправки ставит следующую версию в pending. Устаревший lease не завершает новый job.

Известный отказ Telegram → failed, timeout/network → unknown. Зависший sending
через 60 секунд переводится в unknown, без автоматической повторной отправки.
Для unknown пользователь явно подтверждает риск дубликата перед повтором.
Exactly-once отправка в Telegram не обещается. Карточки бота обновляются;
чужие исходные сообщения бот не редактирует. Отмена помечает карточку «Отменено».
Если message_id неизвестен, worker публикует отдельное уведомление об отмене;
ранее отправленная при таймауте карточка может потребовать ручной правки.

## Приёмка

Тесты: права и подмена chat/topic/event, два пользователя, обе формы создания,
место/ссылки/время, DST, optimistic conflict, конкурентный повтор, парсинг caption,
редактирование, pending/approve, отмена, rollback и отказ между commit/send/result.
PostgreSQL — отдельная тестовая база. Frontend: доступные формы, сохранение draft
после ошибок, фильтры/события, pending/unknown/failed, retry и narrow/dark/focus.
CI: >=90% строк и ветвей отдельно по приложениям, миграция 0001→0002 с данными,
генерация OpenAPI без drift, lint/types/FSD и компиляция без релизной публикации.

Локально проверены upgrade 0001→0002 с заполненными chats/topics и alembic check,
ограничения/FK и конкурентные повторы на PostgreSQL 17. Backend: 112 тестов,
100% измеренных строк и 99.41% ветвей. Область — весь backend/src/planerbot,
включая неимпортированные модули, без ручного исключения продуктового кода.
Frontend: 34 теста, 99.42% строк (174/175) и 94.61% ветвей (246/260) в src,
исключены тесты, test setup и generated .d.ts. Отчёты воспроизводятся командами
из local-development.md и CI. В SQLAlchemy runtime включено hide_parameters,
чтобы ошибки БД не выводили значения места, описания и других полей в логи.

Chromium: 375×812, 1280×900, 812×375; светлая и тёмная темы, отсутствие overflow,
создание события для другого чата/темы, переход к месяцу события и сохранение
настроек проверены с mock API/SDK. Скриншоты просмотрены. Реальная доставка
в Telegram и Android/iOS/Desktop приёмка не проверены без тестового токена
и HTTPS Main Mini App. Browser mock не является проверкой Telegram-интеграции.

Напоминания, отдельный экран дня, повторяющиеся события, полноценные черновики
и история всех версий остаются в плане. Версия события обеспечивает конфликт
правок, но не заменяет журнал аудита прошлых значений. Сессия Mini App пока
ограничена TTL initData, как в каркасе; долгую форму нужно заполнить до истечения.

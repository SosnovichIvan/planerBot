# Требования planerBot

Дата: 2026-10-16. Продуктовые требования согласованы в обсуждении;
технические решения описаны отдельно как предложения.

## Назначение

Один бот подключается администраторами к нескольким Telegram-группам
с темами или без них. Он собирает события и предоставляет персональный календарь.
Место запуска календаря не ограничивает его состав: из чата А пользователь,
состоящий в А и Б, может посмотреть события обоих чатов.

## Обязательные сценарии

1. Назначение бота администратором автоматически подключает чат без `/setup`.
   Бот добавляет команды чата и отправляет кнопку календаря. Администратор
   настраивает часовой пояс, тег событий и разрешённые темы.
2. Пользователь запускает персональный календарь из чата. В общем сообщении
   остаётся кнопка; события других чатов не публикуются в этом чате.
3. Календарь показывает месяц и события, сверху — селект чата с вариантом «Все чаты».
   Фильтры по темам и тегам убраны. В шапке рядом находятся «Создать событие»
   (только для администраторов) и «Обновить события», без вводного текста и бейджа.
4. Администратор создаёт событие через календарь или пошаговый диалог с ботом,
   выбирает управляемый чат и тему. Бот сохраняет событие и публикует карточку
   именно в выбранную тему.
5. Бот распознаёт событие из сообщения с настроенным тегом, включая подпись
   к медиа. Источник определяет чат и тему. Неоднозначные поля требуют
   уточнения или подтверждения по политике администратора.
6. Событие редактируется и отменяется. Изменения формы обновляют опубликованную
   ботом карточку; изменения исходного пользовательского сообщения повторно
   проходят разбор. Бот не редактирует чужие сообщения.

## Поля события

| Поле | Условие |
| --- | --- |
| Название | Обязательно |
| Чат и тема | Чат обязателен; в чате без тем публикация идёт в общий поток |
| Дата начала | Обязательно |
| Время начала и окончания | Время либо режим «весь день»; окончание позже начала |
| Часовой пояс | По умолчанию настройка чата, явно показан при создании |
| Описание | Необязательно |
| Формат встречи | Офлайн / онлайн / гибридная |
| Место встречи | Название места, адрес, ссылка на карту или координаты |
| Ссылка подключения | Необязательна, если указано место/адрес/карта; иначе нужна ссылка |
| Место уточняется | Только для просмотра старых событий; новые требуют места либо ссылки |
| Теги | Тег регистрации и дополнительные категории |
| Источник | Форма календаря / диалог бота / сообщение чата |
| Статус | Черновик / ожидает подтверждения / активно / отменено |

Статус публикации хранится отдельно от статуса события:
ожидает отправки / опубликовано / ошибка / результат отправки неизвестен.

Пример распознаваемого сообщения:

```text
#событие #команда
Название: Встреча команды
Дата: 20.10.2026
Время: 19:00–21:00
Формат: Офлайн
Место: Кафе Маяк
Адрес: Москва, ул. Примерная, 10
Описание: Обсудим планы на следующий месяц.
```

## Доступ

- Видеть событие можно только при подтверждённом текущем членстве в его чате.
- Администратор А не получает доступ к Б из-за своей роли в А.
- Создание через форму и публикация требуют прав администратора целевого чата.
- Парсинг сообщений также разрешён только для администраторов целевого чата.
- `chat_id`, `topic_id`, идентификатор события и callback не являются
  доказательством права доступа; проверка выполняется на сервере.
- Названия чатов, темы, места и количества событий также защищены.
- При невозможности проверить членство выдача данных закрывается.
- После выхода из чата последующие запросы и персональные напоминания не должны
  раскрывать его события. Ранее просмотренные сведения отозвать невозможно.
- Общегрупповая кнопка открытия не содержит персональных данных календаря.

## Критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Участник А и Б запускает календарь из А | Видит события А и Б |
| Участник только А запускает ту же кнопку | События и метаданные Б отсутствуют |
| Пользователь подменяет ID события Б | Сервер не раскрывает объект |
| Участник выходит из Б | Следующий запрос исключает Б |
| Администратор выбирает тему чата Б | Карточка появляется только в этой теме |
| Событие содержит место и адрес | Данные совпадают в календаре и карточке |
| Повторно доставлен update сообщения | Второе событие не создаётся |
| Бот публикует карточку с тегом | Парсер не создаёт из неё дубликат |
| Публикация завершилась ошибкой | Событие сохранено, показана ошибка и доступен повтор |
| Неполная или неоднозначная дата | Событие не активируется без уточнения |
| Отредактирован исходный текст | Существующее событие обновляется с контролем версии |
| Сообщение удалено пользователем | Отмена доступна через бот/календарь; автоматическое обнаружение не обещается |

## Границы первой версии

Включены оба пути создания, персональный Mini App, место встречи, управление
чатами и темами, редактирование, отмена и одно групповое напоминание.
Настройки напоминаний и подтверждения — предложенные значения, уточняются
на этапе каркаса. Повторяющиеся события, AI-разбор свободного текста,
RSVP и внешние календарные подписки отложены.

Не определены: число чатов и событий, ожидаемые пики, целевые latency/SLA,
хостинг, бюджет, срок хранения исходных текстов и политика удаления данных.
До измерений не обещается конкретная производительность.

# События дня, место встречи и клавиатура чата

Контракт изменения: при создании/изменении события требуется место/адрес/карта либо
ссылка подключения, независимо от offline/online/hybrid. Форма больше не
предлагает обход «Место уточняется». Старые события с таким признаком остаются
читаемыми; строгая проверка применяется в EventService перед новой записью.
Права администратора и транзакция event/outbox не меняются. SQL/миграции N/A.

День с событиями — кнопка. По нажатию открывается native dialog с событиями
этого дня из текущего чата/всех доступных чатов. Многодневность и исключительная
полночь совпадают с точками календаря; отменённые события не показываются.
По клику на событие открывается Telegram message_url через openTelegramLink;
обычная ссылка служит fallback вне SDK. Если публикация ещё не имеет message_id
или Telegram не поддерживает ссылку данного типа чата, показывается статус без
ложного перехода. При смене выборки старые события не отображаются.
Для базовых групп без supergroup ID надёжной ссылки на сообщение нет;
переход доступен для супергрупп (в том числе без тем) и forum-тем.
Сохраняется лимит API 200 событий на выборку: при has_more диалог явно сообщает,
что список неполон, и предлагает выбрать конкретный чат.

Общий Modal используется формой и списком дня: начальный фокус, native focus
trap, Escape, восстановление прокрутки; поля и цвета остаются на текущих токенах.

Бот отправляет ReplyKeyboardMarkup с текстовой кнопкой «Календарь», is_persistent,
resize_keyboard и без one_time_keyboard: при подключении, setup и /calendar.
Нажатие кнопки обрабатывается как calendar и возвращает inline-ссылку Mini App.
Уже подключённым чатам после выпуска достаточно один раз вызвать /calendar.
В forum клавиатура отправляется в текущую тему, когда вызов идёт из сообщения.
Это не WebApp-кнопка меню: управление видимостью клавиатуры остаётся у клиента
и пользователя. Текстовая клавиатура может заменять клавиатуру другого бота.

Проверки: место без ссылки, ссылка без места, отказ при отсутствии обоих,
чтение legacy; список дня/переход/статус/доступ; persistent keyboard и её текст;
PostgreSQL, lint/types/coverage, Chromium с mock SDK/API. Реальная Telegram-
приёмка клавиатуры и открытия сообщения нужна после выпуска, включая iOS/Android.
Рабочая ветка → PR develop → PR main → тег; production пока не меняется.

# Маркеры начала, сегодня и проверка рассылки — 2026-10-19

Ветка `fix/calendar-start-today-broadcast`; production в ходе работы не изменялся.

## Контракт исправлений

- Маркер и выбранный день используют `start_date == date`, а не весь интервал.
  Это относится к числу событий, «нужен ответ» и «обновлено». Событие сохраняет
  свои даты окончания/длительность. Отменённые не возвращаются в сетку.
- API/повестка по-прежнему показывают пересекающиеся с месяцем события: это
  существующий контракт, не новый фильтр backend. Старт в прошлом месяце не
  создаёт маркеров в текущем, в том числе при окончании в полночь/переходе года.
- Сегодня в месячной сетке и выборе даты: token-цвет, inset ring, жирный номер,
  подпись «Сегодня» и aria-current=date. Выбор даты — отдельное состояние;
  выбранный сегодня имеет белое кольцо. Геометрия клетки не меняется, красный
  RSVP-маркер не скрывается. Рамка даты — не отключение клавиатурного focus.
- Browser-local today обновляется в полночь, на focus/visibilitychange.
  При выборе разных чатов не навязывается один chat timezone всем календарям.
  В коротком date picker показывается выбранный день либо сегодня за счёт
  прокрутки **только modal-body**, без scrollIntoView внешнего документа.

## Рассмотренный случай недоставки

Read-only проверка VPS: версия 0.1.9, API/bot/worker работают; в последних двух
часах не найдено маркеров ERROR/Traceback/Failed to fetch updates.
На момент проверки в БД пять рассылок, все с audience=yes: четыре notice в sent,
две в skipped. Последняя рассылка имеет два sent с claimed_at
2026-10-19 12:45:23 UTC (15:45:23 Москва). Запросов audience=no не обнаружено.
Skipped сейчас связаны с отменённым событием; точная историческая причина
пропуска отдельно не записывается, её нельзя вывести только из текущего состояния.

Это подтверждение ответа Bot API, **не** доказательство прочтения пользователем
или отображения уведомления Telegram-клиентом. Повтор реальных сообщений для
диагностики не выполнялся, согласия на ЛС/состояния очереди не изменялись.
У пользователя запрошены событие/время и уточнение лички против общего чата.
Конкретный заявленный случай физической недоставки пока не воспроизведён.

Подтверждён пробел UI: после POST показывался только ответ создания с пустым
statuses; обновление доставки требовало отдельного нажатия. Теперь CampaignDelivery
сразу делает GET и повторяет его раз в 3 секунды до терминального состояния.
Пустая аудитория, ожидание, sent/skipped/failed/unknown и ошибка чтения различаются.
После ошибки GET — ручной повтор **только GET**. Повторный POST не выполняется.
При потере прав/сессии старые количества скрываются, зависшие запросы отменяются
при смене campaign/unmount. Сетевой исход создания по-прежнему повторяется
только с исходным Idempotency-Key; разрешения/членство не обходятся.

В первом Cypress-прогоне обнаружено, что асинхронное увеличение блока статусов
сдвигало подтверждение создания под нижнюю границу. Подтверждение перенесено
перед блоком доставки: итог не скрывается после получения GET.

## Данные и проверки

Новых SQL/индексов/миграций/HTTP-полей нет. Используется прежний GET campaign status
с ограниченными агрегатами по campaign_id (PK prefix); авторизация не меняется.
К transport helper добавлен optional AbortSignal, generated OpenAPI не редактируется.
Новые компоненты остаются в pages/calendar/ui; дата/таймер — в shared/lib/date.
Tailwind и прежняя палитра сохранены, внешние пакеты не добавлены.

Unit/component: границы месяца/года, начало/продолжение, отмена, midnight/focus,
selected/current/пустые слоты, автообновление, пустая аудитория, GET error/retry,
отмена и поздние ответы. Backend регрессии отдельно проверяют yes/no, выбор
личного получателя и пропуск сменившего ответ до отправки.
Cypress CAL-09/CAL-10, MSG-07/08/09 связаны с acceptance.md. Снимки today:
4 viewport × 2 темы × 4 состояния (пустой день/встреча/date picker/selected today).
Проверка Chromium не заменяет реальные iPhone/WebKit/экранную клавиатуру и VoiceOver.

# Проверка взаимодействия

Читайте при изменении dialog, menu, tabs, combobox, формы или navigation.

Проверь сначала фактический primitive: native button/dialog либо компонент
дизайн-системы уже может обеспечивать поведение. Не требуй дублировать его.

Для модального окна проверь стартовый focus внутри, замкнутый keyboard path,
закрытие и возврат focus к подходящему элементу. Если инициатор удалён, возврат
должен поддерживать следующий логичный шаг пользователя. ARIA-атрибут сам по
себе не реализует управление focus или блокировку фонового взаимодействия.

Для формы ошибка должна быть связана с полем и объяснять доступный путь
исправления; повтор submit не должен незаметно дублировать операцию. Проверь,
что визуально скрытый контрол не остаётся неожиданной клавиатурной остановкой.

Предпочти один воспроизводимый keyboard-сценарий перечню неподтверждённых
нарушений. Автоматический accessibility scan дополняет ручную проверку, но не
доказывает полное соответствие стандарту.

Первоисточник для уточнения widget-поведения:
[WAI-ARIA APG: Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).
APG описывает шаблоны; не называй каждую рекомендацию отдельным требованием WCAG.

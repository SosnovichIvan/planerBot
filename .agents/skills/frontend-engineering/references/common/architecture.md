# Frontend architecture baseline

Читайте эту справку всегда. Выбранный structure profile определяет конкретные
папки и import boundaries; этот файл задаёт общие инварианты.

## Приоритет правил

1. Явные требования задачи и ближайший agent instructions file.
2. Проверенная конфигурация и устойчивые соглашения целевого workspace.
3. Пользовательский или встроенный structure profile этого skill.
4. Общие рекомендации этого файла.

Не перестраивай существующий проект целиком ради локальной задачи. Если новая
функция не помещается в выбранную структуру без нарушения её границ, обозначь
конфликт и предложи минимальную миграцию отдельно.

## Границы кода

- Группируй бизнес-код по пользовательской возможности или предметной области,
  а не в глобальные папки `components`, `hooks`, `types` без владельца.
- Entrypoint приложения собирает providers, router, error boundaries и startup;
  он не должен становиться хранилищем бизнес-логики.
- Route/page отвечает за композицию сценария. Переиспользуемое поведение живёт
  ниже границы route в модуле с ясным владельцем.
- Общий код не зависит от feature/page. Переноси код в shared только при
  подтверждённой нейтральности и реальном повторном использовании.
- Публичная граница модуля раскрывает минимальный контракт. Не импортируй его
  внутренние файлы из внешнего модуля, если проект использует public entrypoints.
- Один файл имеет один ясный concern, но маленькую связную реализацию не дроби
  ради формального соответствия структуре.

## Состояние и данные

- Server state хранится в принятом query/cache слое со стабильными keys,
  контролируемыми invalidation, retry и stale policy.
- Локальное UI state остаётся у ближайшего владельца; разделяемое client state
  поднимается только до минимальной общей границы.
- Derived state вычисляется из источника, а не синхронизируется копирующими
  effects/watchers.
- Transport client отделён от framework adapter/hook. Внешний payload проходит
  runtime validation на принятой границе; generated contracts не редактируются.
- URL state используй для shareable navigation/filter state, если это принято
  router-моделью проекта.

## UI, безопасность и композиция

- Сначала используй существующие components, tokens, themes и layout primitives.
- Доступность является частью контракта: semantic HTML, keyboard path, focus,
  accessible name, error association и достаточные состояния интерфейса.
- Секреты и доверенные authorization-решения не размещаются в browser bundle,
  storage или UI role checks.
- В microfrontend-системе сохраняй один host/remote contract, lifecycle и способ
  обмена context. Remote не импортирует внутренности другого remote.

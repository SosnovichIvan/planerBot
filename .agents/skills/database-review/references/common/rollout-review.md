# Проверка rollout

Рассмотри схему до/после и матрицу «старый/новый код × старая/новая схема»
только для комбинаций, которые действительно возникают при deployment.

- NOT NULL без источника значения может сломать старые INSERT; наличие
  backfill для старых строк не решает это для новых writes.
- Rename/drop может сломать работающий старый consumer, view, trigger или job.
- Unique constraint может не создаться на текущих duplicates; проверь также
  гонку между preflight и установкой constraint.
- Разрешён ли конкретный DDL внутри транзакции migration runner? Как runner
  записывает частично завершённую операцию и повторяет её после сбоя?
- Backfill с cursor должен быть возобновляемым; обновление новых writes не
  должно быть затёрто старым вычислением. Проверка count не доказывает смысловое равенство.
- Down migration, удаляющая колонку, не восстанавливает её прежнее содержимое.
  Установи доступную точку возврата и пригодность forward recovery.

Не создавай finding на основе несуществующего rolling deploy или размера
таблицы. Если информация критична, укажи условный риск и нужное доказательство.

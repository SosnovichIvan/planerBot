# UI/UX design intelligence

Используй локальный поисковый runtime этого skill для обоснованных дизайн- и
UX-решений. Skill полностью самодостаточен: не предполагай наличие
`frontend-engineering`, `execution-state` или другого skill. Если внешний prompt
подключает несколько skills, верни компактные решения и ограничения, пригодные
для следующего шага, но не управляй соседними skills самостоятельно.

## Границы

- Применяй для visual direction, design system, layout, typography, color,
  interaction, accessibility, charts, responsive и UI/UX review.
- Не запускай для чистой бизнес-логики, API, БД, DevOps или невизуального
  performance work.
- Явные требования пользователя, существующая design system и правила проекта
  имеют приоритет над найденными рекомендациями.
- Dataset — источник вариантов, а не нормативный стандарт. Проверяй соответствие
  продукта, платформы и версии stack; не представляй heuristic как факт.
- Не устанавливай пакеты и не отправляй содержимое проекта во внешнюю сеть.

## Runtime

Найди `scripts/search.py` относительно этого `SKILL.md` и запускай его доступным
Python 3 interpreter. Не используй vendor-specific environment variables или
предположение о текущей директории.

Выбирай минимальный режим:

```text
Новая страница или общее визуальное направление -> --design-system --json
Один UX/design вопрос                         -> --domain <domain> --json
Stack-specific UI guidance                    -> --stack <stack> --json
```

Запрос содержит один основной intent, 2–5 значимых терминов и только полезный
контекст продукта или платформы. По умолчанию запрашивай не более трёх
результатов. Если результат пуст или не соответствует задаче, выполни ровно одну
более узкую попытку с явным domain/stack; затем используй общие знания, явно
отметив отсутствие совпадения.

Доступные domains и подробный query contract смотри, запустив найденный
`<skill-dir>/scripts/search.py` с `--help`; не загружай datasets или исходники
scripts в контекст. Для подробного accessibility/UI review читай
[quick-reference.md](references/quick-reference.md). Для native/mobile polish —
[pro-rules.md](references/pro-rules.md).

## Рабочий процесс

Для полного экрана, пользовательского потока, системы компонентов или handoff
прочитай [design-delivery.md](references/design-delivery.md).

1. Определи продукт, аудиторию, платформу, визуальные ограничения и существующие
   tokens/components. Stack определяй только по явному запросу или проверенной
   конфигурации проекта.
2. Для новой страницы или системы получи один design-system result. Для точечной
   задачи выполни один domain search; не генерируй полную систему без пользы.
3. Проверь top result: domain, source identity, platform fit, contrast и конфликт
   с существующими решениями. Отбрось неподходящие варианты.
4. Сформулируй минимальный контракт результата: visual direction, tokens,
   layout/interaction rules, accessibility constraints, anti-patterns и
   нерешённые вопросы. Не подменяй им архитектурные или framework-правила.
5. Если задача включает реализацию, применяй только разрешённые текущей задачей
   инструменты или skills. Сам факт дизайн-рекомендации не разрешает изменение
   кода или установку dependencies.
6. Перед завершением проверь затронутые состояния и viewport. Не заявляй
   визуальное соответствие без render/screenshot verification, когда оно
   доступно и относится к задаче.

## Сохранение design system

Без `--persist` runtime только читает локальные данные. Сохраняй результат лишь
когда пользователю нужен устойчивый project artifact, всегда передавая явный
`--output-dir` с корнем проекта. Сначала прочитай существующий `MASTER.md`.
`--force` допустим только после явного разрешения пользователя; обычный запуск
не должен перезаписывать существующие решения.

В итоговом ответе отделяй найденные dataset recommendations от собственных
выводов и перечисляй, что было реально проверено визуально.

## Профиль правил проекта

Применяй [профильные правила](references/project-rules.md) только при явном согласии
на правила этого скилла в инструкциях проекта. При наличии approved snapshot
используй его; наличие файла само по себе не активирует правила. Они не запускают другие скиллы автоматически.
